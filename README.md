# SDF Mask Tool

Authoring tool for cel-shading shadow masks. Paint binary masks along a lighting
parameter axis, then bake them into a single SDF texture that the renderer samples
with one threshold comparison.

用于卡通渲染阴影遮罩的绘制工具。在光照参数轴上绘制二值遮罩，烘焙成一张 SDF
贴图；渲染时对每个像素只做一次阈值比较即可得到受光/阴影状态。

---

## 用途

卡通渲染的阴影边界需要随光照方向平滑移动。常见做法是逐帧烘焙多张阴影贴图，
或在着色器里做阈值硬切。本工具把整条光照变化压缩进**一张灰度图的单通道**：

- 贴图中每个像素存一个字节，表示该像素发生翻转时对应的光照参数位置
- 渲染时用当前光照参数与字节值比较，得到二值结果

一张贴图即覆盖整个光照变化范围。

## 贴图约定

贴图为**单通道线性灰度**（非 sRGB）。每个像素存一个值：

| 值 | 含义 |
|---|---|
| `0` | 参数为 0 时即为阴影 |
| `1..252` | 在该参数位置发生翻转 |
| `255` | 全程受光 |

### 两种编码方向

工具会自动判断阴影是**扩张**还是**收缩**，两者编码的语义相反：

| 方向 | texel 表示 | 着色器判据 |
|---|---|---|
| 阴影扩张 | 第一次**被遮**的参数位置 | `lit = texel > t * 0.99` |
| 阴影收缩 | 第一次**受光**的参数位置 | `lit = texel < t * 0.99` |

**方向写在 PNG 的元数据里。** 导出文件含这些 tEXt 块：

| 键 | 值 | 说明 |
|---|---|---|
| `sdf-direction` | `grows` / `shrinks` | 编码方向，决定用上表哪一行 |
| `sdf-invert` | `0` / `1` | 是否启用了「反向」（整条参数轴明暗对调） |
| `sdf-channels` | `gray` / `rgba` | 单通道还是四通道 |
| `sdf-version` | `1` | 贴图语义版本 |

读取方式（Unity / C# 示例）：

```csharp
// 从 PNG 字节里取 tEXt 块的 sdf-direction
// 也可以用任意 PNG 元数据读取库
string dir = ReadPngText(texBytes, "sdf-direction"); // "grows" 或 "shrinks"
bool shrinks = dir == "shrinks";
```

对应着色器（两条都必须实现，运行时按标记二选一）：

```hlsl
float t     = saturate(lightParam) * 0.99;
float texel = SAMPLE(sdfTex, uv).r;

// sdf-direction = grows    ：越过该位置 → 转暗
bool lit = texel > t;

// sdf-direction = shrinks  ：越过该位置 → 转亮
bool lit = texel <= t;
```

`texel` 为 `1.0` 时表示"该像素全程不变"，因此乘 `0.99` 留出上界余量。

> **`shrinks` 用 `<=`。** 工具内部用 `texel <= t` 判定"已越过"，
> 写成严格小于会让恰好落在转变位置上的像素翻转时刻差一格。
> 8bit 下这一点在边界带上可见（每档最多一整列像素）。

> **用错方向的后果**：整张贴图明暗颠倒，100% 的像素都反。
> 早期版本把方向写进 PNG 元数据之前，收缩方向的贴图按默认规则读出来全错。

### 关于「反向」

导出窗口的「反向」是**前置翻转**：写盘前把 texel 换成 `FULL - v`，
等价于整条参数轴的明暗对调。对最终像素取反是另一种做法：它会把
"全程受光 = 255"翻成 0，而 0 是"0 参数就遮"的专用值，语义会撞车。

数学上，反向满足 `flipped(t) == !normal(1 - t)`（对非常量 texel）。
导出窗口里的还原预览已改成同一条语义，所以"看到的"就是"导出的"。

## 参数轴

阴影随光照变化的过程由一条 **0–1 的参数轴**描述。轴上可放置任意数量的
**参数点**，每个参数点保存一张完整的二值遮罩。

- 轴的两端分别对应"光照完全正对表面"与"完全背向"
- 参数点之间由距离场插值过渡，形状按几何距离均匀推进
- 参数轴被等分成固定数量的**刻度**（默认 64，可改）；参数点与播放头都对齐刻度

> **刻度是性能约束。** 拖动时每越过一个刻度才重新采样一次整张图。
> 若允许停在任意连续位置，等价于把刻度数拉到无限大，每移动一个像素就要重算，
> 交互会直接卡死。所以界面显示与落点都对齐刻度，而导出走连续角度轴、精度不受影响。

遮罩要求沿轴**单调**：扩张方向上后一个参数点的遮罩包含前一个，收缩方向反之。
不满足时导出会被拒绝，并在画布上标出违规像素位置。

## 功能

**绘制**

- 笔刷、填充、选区（矩形/套索）、形状（矩形/椭圆）、局部平滑
- 二值遮罩，黑白两色互换（`X`）
- 在无参数点处落笔时自动建立参数点，起点为当前位置的插值结果
- 支持选区内的操作，以及反相、镜像、清空

**参数轴**

- 参数点可添加、删除、拖动、复制到剪贴板后粘贴到任意位置
- 逐点预览，播放头连续移动
- 每个图层含四条独立参数轴（RGBA）

**图层**

- 多图层，每层可切换灰度（仅 R）或 RGBA 四通道模式
- 通道内容可拖拽交换
- 支持混合透明度的叠加预览

**3D 预览**

- 导入 `.obj` / `.fbx` 查看遮罩在模型表面的落点
- 软件光栅化，半兰伯特光照
- 线框、背面剔除、UV 通道切换
- **在画布上叠加 UV 线框**：对照"贴图区域 ↔ 模型部位"。
  3D 面板里有 UV 集选择与「画布显示」开关，也可按 `Ctrl+U` 切换。
  线框画在遮罩之上（否则深色遮罩区里看不见），上限 4 万条边。

**导出**

- 8bit / 16bit 单通道 PNG，或 RGBA 四通道
- 可批量导出全部可见图层
- 导出前显示 SDF 贴图与还原遮罩的双预览

**工程文件**

- `.sdfmask` 为 zip 容器，内含 `project.ron` 与各参数点的 PNG
- 旧版本使用的 `.sdfproj` 仍可打开
- 完整撤销/重做

## 构建

需要 Rust 1.85 或更高版本（edition 2024）。

```bash
cargo build --release
```

生成的可执行文件位于 `target/release/sdf-mask-tool`。

运行：

```bash
cargo run --release
```

## 验证工具

`examples/` 下是长期保留的验证程序，用于确认关键不变量：

| 程序 | 验证内容 |
|---|---|
| `verify_tile` | 分块渲染与单线程渲染逐像素一致 |
| `verify_bake_equiv` | 烘焙优化不改变输出 |
| `verify_grow_fix` | 空帧生长的方向正确 |
| `verify_drag_smooth` | 加参数点与拖动的响应时间 |
| `verify_background_bake` | 后台烘焙的三条前提 |
| `verify_auto_keyframe` | 自动建参数点的行为 |
| `verify_violation_equiv` | 嵌套检测与烘焙判定一致 |
| `viz_growth` | 把生长过程渲染成图，用于目视判断 |

运行方式：

```bash
cargo run --release --example verify_bake_equiv
```

部分程序需要传入模型文件路径：

```bash
cargo run --release --example verify_models -- model1.obj model2.fbx
```

测试：

```bash
cargo test
```

## 已知限制

- 单通道贴图只能表达单向变化：每个像素沿轴翻转一次
- 参数点之间按距离场插值，形状平移时边界会朝多个方向轻微变化
- 3D 预览为 CPU 光栅化，三角形数量上限 120 万
